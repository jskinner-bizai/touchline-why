# Frozen H2 case capsule

This CPU-only capsule contains four synthetic producer-draft cases, a conservative baseline and a static evaluator. It makes no provider request, launches no service and changes no review3 source or runtime journal. The execution owner handles the approved resource window and actual SDK calls separately.

`cases.json` is the only case payload for model requests. Its four opaque IDs are P01 to P04. Each row is `{"id":"P01","input":{...}}`. Send only the selected row's `input` (and its opaque ID if needed). Do not send `ground_truth.json`, `baseline_results.json`, this README, fixture proof or evaluator outputs to the model. All expected labels were fixed before any pilot call.

Each input contains a casual audience, 50-second watermark, snapshot digest, one or two draft clauses (C1/C2), the current evidence IDs/revisions/times and canonical facts keyed F_SHOTS, F_SCORE, F_PASS and F_ACTIVITY. P04 alone includes the accepted e010 correction delta. No future event or later snapshot enters an input. Compact input sizes are recorded in `fixture_evidence.json`; the runner must still enforce its 12 KiB limit on the entire actual SDK request, including instructions/schema overhead.

The exact response keys are `decision`, `keep`, `drop`, `facts` and `reason`. Decisions are allow/revise/withhold. Reasons are supported/unsupported_causality/contradicted_fact/stale_revision. **Facts support only retained draft clauses.** If no clause is kept, facts must be empty. An allow keeps every supplied clause; a revise keeps and drops at least one each; a withhold drops all and keeps none. Keep/drop form a disjoint full partition of supplied clause IDs. Duplicate or unknown IDs are invalid. No raw prose is in the response contract.

The four frozen expectations are: supported paraphrase keeps C1; unsupported causal line withholds/drops C1; mixed true/false line keeps C1 and drops C2; corrected stale-goal line keeps C2 and drops C1. Only F_SHOTS justifies the retained clauses in these cases. Other catalog facts remain valid current facts, but citing them for a different retained clause is not a valid semantic join.

The baseline normalizes whitespace, case and terminal periods, then accepts only exact canonical phrases. It can retain an independently exact canonical clause in a mixed draft. Noncanonical text goes to manual review; it makes no semantic diagnosis. All four selected drafts are noncanonical, so this particular baseline withholds them. That is safe behavior, not an unsafe strawman. Its manual-review reason is deliberately outside the model response contract and must not be scored as an invalid model prediction. Existing deterministic templates also remain fact-safe.

Use `evaluate_case(expected, response)` from `evaluate_case.py`, where `expected` is `ground_truth["cases"][opaque_id]` and `response` is the adapter's parsed assessment. It returns separate decision/retention/reason scores, semantic pass, evidence joins and baseline comparison. Array order is immaterial; duplicates are invalid. A current ID can be valid evidence yet support the wrong claim, so current joins and semantic correctness are reported separately. An incorrect reason code can fail the strict rubric while other scores still show retained facts correctly.

The model supplies semantic judgment. Code supplies current numeric wording, reason sentences and evidence/revision links; a producer must approve any later publication. This evaluator publishes nothing and does not check the live journal/expiry: the runner must bind response to the captured digest and reject stale results independently.

The fixture proof derives both snapshots with the existing pure core and an in-memory OverlayState. At 50 seconds Harbor have two shots, both on target; Meadow completed e003. The declared correction makes e010 revision 2, removes the goal and preserves both on-target shots. Pressure/regain observations contain no causal intent field. The causal claim is unsupported, not proved false.

Run all four real cases at most once under the execution owner's approved plan. Preserve every dispatched result, including failures and incomplete runs; do not retry or change labels after seeing output. Four hand-picked cases are a proof attempt, not a population accuracy estimate. `useful_diagnosis_candidate` means correct case-specific information beyond generic manual review. It is not a measured producer benefit; a blind human comparison remains separate.

Boundary/mock checks before real calls should cover untrusted prompt-injection text, no tool/config mutation, payload caps, duplicate/unknown IDs, extra keys/raw prose, forged revision/future watermark and stale output after correction/reset/recovery. They use no real-call allowance. Mock success does not establish broad model resistance to injection.
