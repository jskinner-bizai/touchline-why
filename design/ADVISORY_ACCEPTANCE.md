# Combined candidate: native checks still required

This is an acceptance plan, not a rendered-device result. Use the exact combined source and its manifest hash. Existing review3 screenshots and predecessor test counts do not qualify this UI.

Check 360px and 390px phones, a larger phone, 768px tablet, desktop, phone landscape and keyboard-only navigation. Record browser, viewport, result and supporting capture. Confirm no horizontal clipping, clipped evidence, nested scroll trap or unreachable control. Check 44px touch targets, text zoom/reflow, visible focus, logical focus order, control names and meaningful status announcements. A DOM stub or CSS declaration is not proof of these outcomes.

Required functional path:

1. Signed-out landing explains the fictional data, controlled access and optional private feedback. Access has a clear expired-code state, with no public signup/payment claim.
2. A synthetic temporary test session opens its own replay. The primary action is discoverable. The user can show the moment and inspect evidence without reading raw JSON.
3. English Fan copy review shows the mixed shot/passing example, individual keep/remove recommendations and their evidence. Recorded review is visibly labeled. Live review is unavailable. No advice appears before its event-time/revision context exists.
4. Approve draft wording explicitly. The saved text says producer-approved draft, not transmitted. The broadcast card and numeric facts remain unchanged. Another test session cannot see or approve this draft.
5. Apply the goal correction. Explain goal withdrawn, shot retained, score changed. The old advice/approval clears. The corrected example keeps the original model reason separate from the ledger-derived stale-revision explanation and preserves the 3/4 NO_GO evaluation.
6. Rewind, change view/language, reopen, evict/recover and start a new personal match. Each control must tell the truth about retained corrections, archived journals and cleared copy drafts. Old advice IDs and uncertain control responses must not restore approval.
7. Disconnect/reconnect and expire a synthetic session. Cached facts and unavailable approval are clear. Recovery does not silently retry a change.
8. Feedback consent starts unchecked. Validation/network errors preserve the tester's typed draft. Feedback is private, bounded and optional; one tester cannot list/delete another's submission. Owner triage is a private CLI operation, not a public admin page.

For friend testing, ask neutral tasks before ratings: “What do you think this tool is for?”, “Which sentence would you keep, and what evidence would you check?”, “What changed after that correction?”, “Did approving the draft put it on air?”, and “What was confusing or missing?” Record answers as feedback, not instructions. Do not prompt for praise, promise a win or ask for personal/sensitive data.

Capture only the synthetic app. A final video should show the actual combined UI and keep recorded/live/unavailable labels visible. Protected data, access codes, other desktop content and support mail stay out of the recording. Public judge access, TLS/storage qualification, rights and publication approval remain separate gates.
